M5 · Failure handling and monitoring

When something goes wrong, the tool says so clearly

If this happensThe tool does this
Not a PDF or broken fileClear error message
Password-locked PDFAsks for an unlocked copy
Scanned PDF, no textAsks to run OCR first
Over 700 pages or 60 MBRejects with the limit
Summary AI is downWrites a summary from the findings
AI claim with no evidenceDrops the claim, logs it

What we watch for each report

One log line: pages, sentences, flags per type, time per step, and how many scores were unsure (0.35 to 0.65).

Alarm if the flag rate or the unsure share moves more than 2× from normal. That means a new report format or sector.

Alarm if the summary AI fails more than 10% of the time.

12 ·Privacy: reports are public filings, and the tool profiles companies, not people.

A real product must fail safely. On the left are the main things that can go wrong and what the tool does. A broken file, a locked file or a scanned file each get a clear message telling the user what to do. Very large files are rejected with the limit. If the summary AI is down or out of credit, which happened to us with Gemini, the tool still writes a summary built straight from the findings. And if the AI writes a claim that no found sentence supports, the checker removes it. On the right is monitoring. Every report writes one log line with its counts and timings, plus how many scores were unsure. If the flag rate or the unsure share suddenly doubles, that is an alarm, because it usually means a new kind of report the model was not trained on. On privacy: these are public filings, and we profile companies, not people.
